\section{Introduction}

Tools that help maintain a test suite tend to rely on a few cheap signals. Two tests that execute the same lines look redundant. A test that has not failed in a few runs looks stable. A function whose deletion breaks a test looks protected. Each signal is quick to compute, and each can be wrong in ways that matter if a tool turns it into advice to delete or skip tests.

As coding agents write more of the code, the tests that check it become the main line of defence, and \citet{osmani2026verification} argues that verification, through properties, differential checks and deterministic feedback, becomes central to agent-assisted development. That makes the tests themselves worth verifying. We are building Agentic Verification, a Claude Code plugin that audits a pytest suite and reports evidence about cost, intermittent failures, coverage overlap and fault detection. Its product requirements~\cite{tsaprd} commit to several rules drawn from published work, most of it on Java. Overlap must never be reported as redundancy. A killed whole-function mutant must not be taken to protect the function's individual effects. Tests that are each removable on their own must be validated as a group before any combined removal. Per-test coverage must be measured separately from runtime profiling because it adds overhead. A short run without failures must be reported as ``not observed'' rather than ``stable''.

This study tests whether those rules hold on mature open-source Python projects, before the plugin depends on them. We pre-registered six hypotheses (H1 to H6), pinned eight projects at release commits, and ran every experiment with the same instrument the plugin uses. The hypotheses, metrics and decision rules were committed to the repository before data collection; deviations are listed in the pre-registration file and summarised in Section~\ref{sec:threats}.

The contributions are:
\begin{itemize}
  \item a replication on Python of the statement-level pseudo-testedness result previously reported for Java~\cite{maton2024pseudo} (H3);
  \item measurements of how often high coverage overlap and leave-one-out redundancy mislead on real suites (H1, H4);
  \item a cost comparison of deterministic deletion mutants against mutmut's classical operators under equal budgets (H2);
  \item measured overhead of per-test coverage contexts (H5) and a repeat-run flakiness survey (H6);
  \item a pre-registered benchmark of the plugin's skill against the same agent without it, with every claim checked independently (Section~\ref{sec:benchmark});
  \item the raw data, analysis scripts and instrument, released with the plugin.
\end{itemize}
